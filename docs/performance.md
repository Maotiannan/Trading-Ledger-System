# 性能基线与约束

本文记录 MULEDGER 当前首屏性能优化的边界，避免后续功能改动重新增加无效请求。

## 当前约束

- 工作区身份仍由服务端接口校验；已有登录状态只用于并行显示工作区，不能作为权限依据。
- 侧边栏不在打开页面后自动加载所有菜单的数据。页面预加载只在菜单悬停、聚焦或明确切换时发生。
- 用户偏好在同一轮首屏加载中只允许一个进行中的请求，仪表盘的布局和分页偏好共享该请求。
- 客户分析卡片使用可视区域加载。卡片接近视口时才请求分析数据，切换分析标签仍按需请求。
- 财务余额必须继续使用统一的实时计算结果，不能为了减少响应时间改回只读取 `Order.orderBalance`。
- Receipt、Payment Detail、SWIFT 的列表后端分页本轮明确保持现状，不得把本次优化描述为已完成后端分页。

## 修改后验证

至少验证以下行为：

1. 仪表盘初始渲染不会为所有侧边栏菜单发起业务列表请求。
2. 布局和分页偏好同时加载时只发起一个 `settings?view=user-preferences` 请求。
3. 已登录用户进入工作区时，身份复核与工作区数据请求可以并行；身份失效仍回到登录页。
4. 客户分析卡片离开首屏时不会立即请求分析接口，滚动接近卡片后才请求。
5. Dashboard 余额、客户欠款和发票欠款仍由实时余额计算路径提供。

## 后续测量

真实优化效果应使用已登录浏览器的 Network 时间线记录：

- 首次打开：登录检查、首屏 HTML、Dashboard summary、首屏 JS 执行完成时间。
- 再次打开：缓存命中后的可操作时间。
- 页面切换：路由响应、列表接口响应和返回体大小。

只看公网 HTML 的 `curl` 时间不能代表完整登录后的页面体验，也不能单独用来判断 Cloudflare、手机网络或数据库哪一层是瓶颈。
